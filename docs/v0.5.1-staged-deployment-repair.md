# v0.5.1 Staged Dedicated-Host Repair

This candidate repairs two deployment boundaries without changing the MCP
runtime, launcher behavior, six tool schemas, structured outputs, or public
tool-contract version v0.4.3. It remains staged outside the frozen v0.5.0
product tree until an authorized integration step.

## H-01: reproducible offline Python closure

The former runbook installed the MCP wheel without enforcing the dependency
versions and hashes resolved by the development lock. The repair adds:

- `deployment/windows/python-dependencies.lock.txt`, a Windows CPython 3.13
  AMD64 target-specific, marker-free, exact-version/artifact-hashed runtime
  export narrowed from the frozen development lock;
- `deployment/windows/python-runtime-inventory.json`, the exact expected
  Windows CPython 3.13 x64 installed distribution set;
- `src/dispenser_conditioning_mcp/deployment_inventory.py`, a strict local
  inventory validator; and
- `deployment/windows/release_bundle_manifest.py` and its closed JSON Schema,
  which create and verify the exact artifact filename/hash set, open every
  dependency/MCP wheel to validate its paths, dist-info identity, and internal
  target tags, and prove wheel-to-lock-to-inventory correspondence;
- `deployment/windows/New-DispenserMcpPythonRuntimeManifest.ps1` and
  `Test-DispenserMcpPythonRuntime.ps1`, which verify the approved offline
  installer's hash/Authenticode signer and co-record that identity with every
  file in a procedurally clean CPython runtime tree; and
- `deployment/windows/Install-DispenserMcpPython.ps1`, which blocks an
  incomplete manifest-declared wheelhouse before it resolves or mutates the
  virtual environment, validates the complete base runtime and Python payload,
  clears inherited index settings, installs with
  `--offline --no-index --require-hashes`, installs the verified MCP wheel with
  `--no-deps`, and blocks on installed-inventory drift.

The deployment host cannot use a package index. A controlled release
workstation must populate a reviewed Windows wheelhouse and publish an
independently authenticated artifact manifest. The current local cache is
sufficient to regenerate the lock export but is not a complete distributable
wheelhouse, so no such bundle is claimed by this candidate.

The runtime-tree manifest detects byte drift but neither proves that the named
installer caused the runtime tree nor makes a supplied expected installer hash
or signer thumbprint trustworthy by itself. Clean-install provenance remains a
blocking operator procedure. Those values and the resulting manifest hash must
come through independent site software-approval channels; the runtime root
remains outside service/agent write authority.

## H-02: allow-only Windows ACL boundary

The former `icacls /inheritance:r` and `/grant:r` sequence did not remove an
unrelated explicit ACE. The repair adds:

- `deployment/windows/Initialize-DispenserMcpProtectedRoot.ps1`, which refuses
  reuse, validates the exact operator and non-administrator local service users,
  applies the protected root DACL/owner before descendants exist, and builds
  every policy-directory DACL from an empty ACL; and
- `deployment/windows/Test-DispenserMcpAcl.ps1`, which recursively validates
  the installed tree against an exact SID/right/owner/inheritance/propagation
  allowlist and blocks on
  any unknown SID, duplicate/deny ACE, excessive/insufficient service right,
  missing required identity, unapproved owner, reparse point, noncanonical ACL,
  or unprotected policy directory.

The allowed DACL identities are BUILTIN\\Administrators, SYSTEM, the exact
resolved deployment operator, and the exact resolved service user. The service
user must be an enabled local user and cannot be a direct local Administrators
member. The runbook separately requires an effective-token group/privilege
review under that identity.
It receives read/execute on the application, dependency, venv, configuration,
and authentication trees and Modify only on `state/unloaded-hil` and `logs`.
The operator is the required owner except that service-created objects are
allowed below those two writable trees. The AI execution identity is not
allowed.

## Verification scope

Offline tests cover strict inventory and release-manifest parsing,
exact/missing/extra/version/hash and platform drift, an incomplete wheelhouse
rejected before any environment mutation, complete-runtime tree verification,
fresh-root refusal, Administrators-member rejection before root creation,
root protection before descendant creation, rejection of a surviving explicit
Users ACE and inheritance-flag drift, owner validation, and successful
recursive validation.
Full lint, static typing, unit/protocol tests, build, archive inspection, packed
smoke, and Inspector discovery are required before integration is proposed.
